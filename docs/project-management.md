# Gestión del Proyecto: QuickNotes
 
## Metodología
 
Para este proyecto utilizo **Kanban**, ya que es un proyecto individual sin sprints fijos. Kanban me permite visualizar el estado de cada tarea y moverla según avanzo, sin necesidad de planificar iteraciones cerradas.
 
## Tablero Trello
 
El tablero está organizado con las siguientes columnas:
 
- **Backlog**: todas las tareas identificadas pero aún no comenzadas
- **Todo**: tareas priorizadas para la semana actual
- **In Progress**: tarea en la que estoy trabajando ahora mismo
- **Review**: tareas completadas que necesito revisar o probar
- **Done**: tareas finalizadas y validadas

## Organización de tareas
 
Cada funcionalidad del proyecto tiene su propia tarjeta en Trello. Dentro de cada tarjeta añado:
 
- Una descripción breve de qué hay que hacer
- Una checklist con las subtareas técnicas concretas
- Una etiqueta por área: `Frontend`, `Backend`, `IA`, `Docs`, `Testing`
## Flujo de trabajo
 
1. Selecciono una tarea del **Backlog** y la muevo a **Todo**
2. Cuando empiezo a trabajar en ella, la muevo a **In Progress**
3. Al terminar la implementación, la muevo a **Review** y la pruebo manualmente
4. Si funciona correctamente, la muevo a **Done**
## Priorización
 
Las tareas están priorizadas en este orden:
 
1. Estructura base del proyecto (hecha)
2. Backend: CRUD de notas con Express
3. Frontend: componentes y páginas principales
4. Integración con la API de Claude
5. Funcionalidades opcionales (búsqueda, modo oscuro, etc.)
6. Testing, despliegue y documentación final
